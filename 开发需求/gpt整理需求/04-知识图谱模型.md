# 1. 文档目标

本文档用于定义系统知识图谱（Knowledge Graph）模型。

知识图谱负责：

* 组织实体关系
* 组织业务关系
* 支持复杂查询
* 支持Agent推理
* 支持知识沉淀
* 支持经验复用

---

# 2. 为什么需要知识图谱

传统数据库擅长回答：

```sql
某项目有多少任务？
```

```sql
某文件是谁上传的？
```

但是不擅长回答：

```text
未来城项目中

由张三负责

且与施工图有关

同时产生整改任务

最终影响验收结果

的全部业务链路是什么？
```

这种问题本质是：

```text
关系查询
```

而非数据查询。

---

# 3. 图谱定位

系统采用：

```text
PostgreSQL
负责事实存储

Neo4j
负责关系存储
```

---

职责划分：

```text
PostgreSQL
记录发生了什么

Neo4j
记录它们之间有什么关系
```

---

# 4. 图谱核心思想

系统采用：

```text
Entity
+
Relationship
+
Event
```

模式。

---

图谱中的一切都由：

```text
节点(Node)

关系(Relationship)
```

组成。

---

# 5. 一级节点定义

系统定义七类核心节点。

```text
Person

Company

Project

Task

File

Conversation

Event
```

与实体模型保持一致。

---

# 6. Person节点

表示自然人。

---

示例：

```yaml
Person

id: PERSON-001

name: 张三

position: 设计经理
```

---

# 7. Company节点

表示组织。

---

示例：

```yaml
Company

id: COMPANY-001

name: XX地产
```

---

# 8. Project节点

表示项目。

---

示例：

```yaml
Project

id: PROJECT-001

name: 长沙未来城
```

---

# 9. Task节点

表示任务。

---

示例：

```yaml
Task

id: TASK-001

title: 完成施工图审核
```

---

# 10. File节点

表示文件。

---

示例：

```yaml
File

id: FILE-001

name: 景观施工图V3.pdf
```

---

# 11. Event节点

表示业务事件。

---

示例：

```yaml
Event

id: EVENT-001

type: drawing_upload
```

---

# 12. 关系定义原则

图谱中的价值不在节点。

而在关系。

---

例如：

```text
张三
```

价值有限。

---

但：

```text
张三

负责

未来城项目
```

开始有意义。

# 18. Event作为关系中心

这是系统最重要的设计。

---

很多系统：

```text
项目

↓

文件
```

直接关联。

---

本系统：

```text
项目

↓

事件

↓

文件
```

关联。

---

例如：

```text
未来城项目

↓

上传施工图

↓

景观施工图V3.pdf
```

---

这样能够回答：

```text
为什么会产生这个文件？
```

---

# 19. 事件链

系统支持事件链。

---

例如：

```text

↓

↓

↓

↓

材料进场

↓

验收
```

形成：

```text
Event

↓

NEXT_EVENT

↓

Event
```

# 30. 设计结论

团队大脑知识图谱本质上是：

```text
Entity

+

Relationship

+

Event
```

组成的业务网络。

其中：

Entity负责描述对象。

Relationship负责描述联系。

Event负责驱动关系产生。

最终形成：

```text
人

↓

项目

↓

事件

↓

任务

↓

文件

↓

知识

↓

标准
```

的企业知识演化网络。

Neo4j并不是数据仓库。

而是企业大脑中的关系神经网络。

所有Agent都将通过该网络进行知识发现、业务追溯与经验复用。
