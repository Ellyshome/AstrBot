# 1. 阶段目标

第一阶段目标是尽快跑通 IM 入口下的最小业务闭环。

核心闭环：

```text
IM消息接入
→ 消息入库
→ 意图识别
→ 文件/会议/任务/事件基础处理
→ 简单查询问答
→ IM回复
```

第一阶段不追求复杂自动化，只要系统能被真实用户通过 IM 使用，并能稳定沉淀资料、会议、任务和事件即可。

3. 可以输出结构化日志。

# 7. T03 AstrBot接入

## 目标

让 AstrBot 消息能进入团队大脑模块。

## 任务

1. 编写 AstrBot 插件入口。
2. 接收文本消息。
3. 接收群聊和单聊上下文。
4. 调用 `handle_im_message()`。
5. 将处理结果回发 IM。

## 完成标准

1. 用户在 IM 发送消息后，系统能收到。
2. 系统能打印标准日志。
3. 系统能回复一条测试消息。

---

# 8. T04 消息标准化与入库

## 目标

所有 IM 消息必须先入库。

## 任务

1. 实现 `normalize_message()`。
2. 生成 event_id。
3. 创建或查找 conversation。
4. 写入 messages。
5. 保存 AstrBot 原始 payload。

## 完成标准

1. 每条消息都有 event_id。
2. messages 表可查到原始消息。
3. 群聊和单聊都能区分。
4. 普通消息不会丢失。

---

# 9. T05 用户与IM账号映射

## 目标

识别消息发送人对应的系统用户。

## 任务

1. 建立 user_im_bindings 表。
2. 根据 `im_platform + im_user_id` 查询用户。
3. 未绑定用户允许消息入库，但限制业务写入。
4. 提供管理员手工插入绑定的方式。

## 完成标准

1. 已绑定用户可正常触发业务。
2. 未绑定用户会收到绑定提示。
3. 未绑定用户消息仍然入库。

---

# 10. T06 路由Agent

## 目标

识别用户消息意图。

## MVP意图

```text
chat
event_record
file_upload
meeting_record
task_record
query
unknown
```

## 任务

1. 编写关键词规则。
2. 文件消息优先识别为 file_upload。
3. 包含“会议/纪要”识别 meeting_record。
4. 包含“任务/负责/截止”识别 task_record。
5. 包含“记录/上报/完成/验收”识别 event_record。
6. 包含“查/查询/哪些/有没有”识别 query。

## 完成标准

1. 常见消息能识别到正确 intent。
2. 识别结果写入 events 或日志。
3. unknown 不影响系统运行。

---

# 11. T07 事件记录

## 目标

支持通过 IM 录入普通业务事件。

## 任务

1. 根据消息生成事件标题。
2. 根据关键词生成 event_type。
3. 绑定 user_id。
4. 能识别项目则绑定 project_id，不能识别可为空。
5. 写入 events。
6. 回复事件编号。

## 完成标准

输入：

```text
记录一下，今天1号楼地下室防水验收完成。
```

结果：

1. messages 有原始消息。
2. events 有业务事件。
3. 用户收到“已记录”。

---

# 12. T08 文件记录

## 目标

支持 IM 上传文件后归档元数据。

## 任务

1. 从 AstrBot 获取附件信息。
2. 保存文件名、类型、大小、来源。
3. MVP 可先保存 AstrBot 文件路径，后续再转 MinIO。
4. 写入 files。
5. 回复文件编号。

## 完成标准

1. 上传文件能生成 file 记录。
2. 文件和消息通过 event_id 关联。
3. 用户收到文件归档提示。

---

# 13. T09 会议记录

## 目标

支持会议纪要文本或文件的基础入库。

## 任务

1. 识别“会议/纪要/例会”等关键词。
2. 文本消息直接写入 meetings.summary。
3. 文件消息关联 file_id。
4. 可选：从文本中简单抽取任务。
5. 回复会议记录编号。

## 完成标准

输入：

```text
会议纪要：张三负责周五前完成入口整改。
```

结果：

1. meetings 有记录。
2. 如能抽取任务，则 tasks 有记录。
3. 用户收到确认回复。

---

# 14. T10 任务记录

## 目标

支持从 IM 文本创建任务。

## 任务

1. 抽取任务标题。
2. 抽取责任人文本。
3. 抽取截止时间文本。
4. 匹配系统用户，无法匹配则先保存为文本。
5. 写入 tasks。
6. 回复任务编号。

## 完成标准

输入：

```text
任务：张三下周五前完成1号楼入口整改。
```

结果：

1. tasks 有记录。
2. owner_id 可为空但 owner_text 要保存。
3. 用户收到任务编号。

# 15. T11 简单查询问答

## 目标

支持基础查询，先不做复杂推理。

## 查询范围

```text
项目
文件
会议
任务
事件
```

## 任务

1. 识别 query intent。
2. 支持查询未完成任务。
3. 支持查询某项目文件。
4. 支持查询最近会议。
5. 支持查询最近事件。
6. 可选：接入 document_chunks 做简单 RAG。

## 完成标准

输入：

```text
查一下还有哪些未完成任务？
```

结果：

1. 返回任务列表。
2. 无结果时明确回复。

# 16. T12 IM回复

## 目标

所有关键操作有明确反馈。

## 任务

1. 封装 `send_reply()`。
2. 支持群聊回复。
3. 支持单聊回复。
4. 群聊普通消息默认不回复。
5. 业务成功/失败必须回复。
6. Agent 回复也写入 messages。

## 完成标准

1. 用户能收到成功回复。
2. 用户能收到失败原因。
3. 回复消息可追溯。

---

# 17. T13 异常日志

## 目标

系统失败时可定位。

## 任务

1. 所有入口 try/catch。
2. 数据库错误记录日志。
3. AstrBot 发送失败记录日志。
4. 意图识别失败降级为 chat。
5. 写入 events，event_type = system_error。

## 完成标准

1. 异常不会导致主进程崩溃。
2. 错误日志包含 event_id。
3. 用户能收到简短失败提示。

# 20. 第一阶段完成定义

满足以下条件即可认为第一阶段可以试运行：

1. 用户可通过 IM 与系统交互。
2. 所有消息可追溯。
3. 可录入事件。
4. 可上传并记录文件。
5. 可录入会议纪要。
6. 可创建任务。
7. 可查询未完成任务和最近资料。
8. 系统可回复成功或失败结果。
9. 基础异常有日志。
10. 数据全部落入 PostgreSQL。
