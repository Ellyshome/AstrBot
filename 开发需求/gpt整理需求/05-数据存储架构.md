# 1. 文档目标

本文档用于定义团队大脑系统的数据存储架构。

主要解决：

* 数据存哪里
* 文件存哪里
* 关系存哪里
* 向量存哪里
* Agent状态存哪里

以及：

```text
各存储组件职责边界
```

避免重复存储与职责混乱。

---

# 2. 架构原则

系统采用：

```text
Single Source Of Truth
```

原则。

即：

```text
结构化事实

只能有一个权威来源
```

---

例如：

项目名称：

```text
长沙未来城
```

只能存在于：

```text
PostgreSQL
```

作为唯一事实源。

---

其他系统：

```text
Neo4j

向量库

缓存
```

均属于派生数据。

---

```text
组织

项目

任务

事件

权限

工作流

审计日志
```

### 人员


---

---

### 任务



# 5. MinIO定位

## 文件仓库

MinIO只存文件。

---

不存：

```text
文件关系

文件权限

文件业务信息
```

---

这些全部放PostgreSQL。

---

## 存储内容

```text
pdf

docx

xlsx

pptx

dwg

jpg

png

mp4

mhtml
```

---

## 示例

```text
MinIO

/project-001/

    drawing/

    photo/

    contract/

    report/
```

---

## PostgreSQL记录

```yaml
file:
    id:
    name:
    object_path:
```

---

真实文件：

```text
MinIO
```

---

元数据：

```text
PostgreSQL
```

---

# 6. Neo4j定位

## 企业关系网络

Neo4j不存业务事实。

只存：

```text
关系
```

---

例如：

```text
张三

参与

未来城项目
```

---

保存：

```text
(Person)

↓

PARTICIPATES_IN

↓

(Project)
```

---

## 核心职责

```text
关系查询

业务追溯

知识发现

Agent导航
```

---

## 存储内容

节点：

```text
Person

Project

Task

File

Event

Role

Agent
```

---

关系：

```text
PARTICIPATES_IN

UPLOADS

TRIGGERS

GENERATES

BELONGS_TO
```

---

## 不存内容

禁止存：

```text
文件内容

合同正文

图纸数据

聊天原文
```

# 7. Vector DB定位

## 语义检索层

向量库负责：

```text
语义相似度搜索
```

---

例如：

用户问：

```text
有没有类似的景观样板区问题？
```

---

向量库负责找：

```text
语义相似案例
```

---

## 存储内容

文档切片：

```text
Chunk
```

---

例如：

```text
设计导则

会议纪要

验收记录

经验总结
```

---

## 推荐结构

```yaml
chunk_id:
file_id:
project_id:
text:
embedding:
```

---

## 禁止存储

禁止把完整业务实体放入向量库。

例如：

```text
项目

任务

权限
```

---

这些属于关系数据。

# 14. 数据同步原则

所有数据流：

```text
PostgreSQL

↓

同步

↓

Neo4j
```

---

```text
PostgreSQL

↓

同步

↓

Vector DB
```

---

禁止：

```text
Neo4j

↓

修改

↓

PostgreSQL
```

---

禁止：

```text
Vector DB

↓

修改

↓

PostgreSQL
```

---

即：

```text
PostgreSQL
永远是主数据源
```

# 16. 设计结论

团队大脑采用五层存储架构：

```text
PostgreSQL
    ↓
业务事实

MinIO
    ↓
文件仓库

Neo4j
    ↓
关系网络

Vector DB
    ↓
语义检索

Redis
    ↓
实时状态
```

其中：

```text
PostgreSQL
是唯一事实源
```

所有Agent、工作流、知识图谱、向量检索最终均以PostgreSQL中的业务数据为准。

系统遵循：

```text
事实层

↓

关系层

↓

知识层

↓

Agent层
```

逐层构建企业数字大脑。
