# 1. 文档目标

本文档定义系统状态机（State Machine）模型。

用于解决：

* 实体有哪些状态
* 状态如何变化
* 哪些变化合法
* 哪些变化非法
* Agent如何执行状态变更

---

# 2. 什么是状态机

状态机表示：

```text
一个对象允许处于哪些状态
```

以及：

```text
状态之间允许如何转换
```

---

例如：

任务：

```text
待处理

进行中

已完成

已关闭
```

---

不是任意切换。

例如：

```text
待处理

↓

已完成
```

可能不允许。

---

必须：

```text
待处理

↓

进行中

↓

已完成
```

---

这就是状态机。

---

# 3. 为什么需要状态机

没有状态机：

```text
Agent随意改状态
```

---

可能出现：

```text
未审批

↓

已付款
```

---

或者：

```text
未验收

↓

已交付
```

---

产生业务错误。

---

因此：

```text
Workflow组织流程

State Machine约束状态
```

---

# 4. Workflow与状态机区别

## Workflow

回答：

```text
下一步做什么
```

---

例如：

```text
上传图纸

↓

审核

↓

归档
```

---

## State Machine

回答：

```text
允许变成什么状态
```

---

例如：

```text
Draft

↓

Reviewing

↓

Approved

↓

Archived
```

# 6. 状态机核心模型

状态机由：

```text
State

+

Transition

+

Rule
```

组成。

---

# 7. State定义

State表示：

```text
对象当前状态
```

---

例如：

任务：

```text
todo

doing

completed

closed
```

---

# 8. Transition定义

Transition表示：

```text
状态转换
```

---

例如：

```text
todo

↓

doing
```

---

就是一次Transition。

---

# 9. Rule定义

Rule表示：

```text
什么时候允许转换
```

---

例如：

```text
负责人确认
```

---

才允许：

```text
doing

↓

completed
```

---

# 23. Agent与状态机

Agent无权直接修改状态。

---

必须：

```text
Agent

↓

State Engine

↓

Entity
```

---

例如：

DesignAgent：

```text
申请状态变化
```

---

State Engine：

```text
审核合法性
```

---

通过后：

```text
更新数据库
```

---

# 24. 权限与状态机

状态变化同时检查权限。

---

例如：

```text

```

只能：

```text
审批人
```

执行。

---

即：

```text
RBAC

+

State Machine
```

联合校验。

# 38. 设计结论

团队大脑采用：

```text
Workflow

+

State Machine
```

双引擎架构。

其中：

Workflow负责：

```text
做什么
```

---

State Machine负责：

```text
能不能做
```

---

Agent负责：

```text
执行
```

---

最终形成：

```text
Event

↓

Workflow

↓

Agent

↓

State Machine

↓

Entity
```

的统一业务执行体系。

状态机将成为整个企业数字大脑的业务规则底座。
