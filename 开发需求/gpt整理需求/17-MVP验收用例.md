# 17-MVP验收用例

> 团队大脑 Agent 系统  
> 文档版本：V1.0  
> 最后更新：2026-06  
> 状态：MVP验收文档

---

# 1. 文档目标

本文档定义 MVP 第一阶段的验收用例。

用于判断系统是否已经满足：

```text
可以通过 AstrBot / IM 入口试运行
```

验收重点不是功能完整，而是确认最小闭环可用、可追溯、可扩展。

---

# 2. 验收范围

MVP 第一阶段验收以下能力：

```text
AstrBot消息接入
消息入库
用户IM绑定
意图识别
事件录入
文件记录
会议记录
任务创建
简单查询
IM回复
异常处理
```

不验收：

```text
Neo4j知识图谱
完整Workflow
完整State Machine
复杂RBAC
自动审批
多Agent协同
ERP/OA/CAD集成
```

# 5. P0-01 AstrBot 消息接入

## 目标

确认 AstrBot 能把 IM 消息交给团队大脑模块。

## 前置条件

1. AstrBot 已启动。
2. 团队大脑插件已加载。
3. 测试用户张三已绑定 IM。

## 输入

用户发送：

```text
你好
```

## 期望结果

1. 系统日志出现消息接收记录。
2. 生成 `event_id`。
3. `messages` 表中出现该消息。
4. 系统不报错。

## 通过标准

消息进入系统并成功入库。

等级：P0

---

# 6. P0-02 单聊普通消息入库

## 输入

张三单聊发送：

```text
今天下午三点开个内部沟通会。
```

## 期望结果

1. `messages` 新增一条记录。
2. `conversation_type = private`。
3. `direction = user_to_agent`。
4. `intent = chat` 或仅作为普通消息处理。
5. 不创建任务。
6. 不创建业务事件。

## 通过标准

普通消息可留痕，不误触发业务。

等级：P0

---

# 7. P0-03 群聊普通消息入库

## 输入

张三在群聊发送：

```text
大家注意一下，明天上午现场集合。
```

## 期望结果

1. `messages` 新增记录。
2. `conversation_type = group`。
3. `group_id` 有值。
4. 默认不回复，避免群聊刷屏。
5. 不误创建业务数据。

## 通过标准

群聊消息可留痕，默认安静处理。

等级：P0

---

# 8. P0-04 事件录入

## 输入

张三发送：

```text
记录一下，今天未来城项目1号楼地下室防水验收完成。
```

## 期望结果

1. `messages` 写入原始消息。
2. 系统识别 `intent = event_record`。
3. `events` 新增业务事件。
4. 事件内容包含原始描述。
5. 如能识别项目，则关联未来城项目。
6. 系统通过 IM 回复：已记录。

## 回复示例

```text
已记录该事件。
事件编号：EVT-20260605-000001
```

## 通过标准

事件可从 IM 录入并收到确认。

等级：P0

---

# 9. P0-05 未绑定用户业务录入限制

## 输入

未绑定用户李四发送：

```text
记录一下，今天材料进场验收完成。
```

## 期望结果

1. `messages` 仍然写入。
2. 系统识别发送人未绑定。
3. 不写入正式业务事件，或写入待确认事件。
4. 系统回复绑定提示。

## 回复示例

```text
已收到消息，但尚未识别您的系统身份。请联系管理员绑定账号后再进行业务录入。
```

## 通过标准

未知用户消息不丢失，但不能直接写入正式业务数据。

等级：P0

---

# 10. P0-06 任务创建

## 输入

张三发送：

```text
任务：王五下周五前完成未来城项目1号楼入口整改。
```

## 期望结果

1. `messages` 写入原始消息。
2. 系统识别 `intent = task_record`。
3. `tasks` 新增任务。
4. 任务标题包含“1号楼入口整改”。
5. 责任人文本保存为“王五”。
6. 截止时间能识别则保存，不能识别则保留原文。
7. 系统回复任务编号。

## 回复示例

```text
已创建任务。
任务编号：TASK-20260605-000001
```

## 通过标准

可通过 IM 创建基础任务。

等级：P0

---

# 11. P0-07 会议记录入库

## 输入

张三发送：

```text
会议纪要：未来城项目工程例会，王五负责周五前完成入口整改，赵六负责提交材料清单。
```

## 期望结果

1. `messages` 写入。
2. 系统识别 `intent = meeting_record`。
3. `meetings` 新增会议记录。
4. 会议摘要保存原文。
5. 可选：抽取出 1-2 条任务。
6. 系统回复会议记录编号。

## 通过标准

会议纪要可通过 IM 录入。

等级：P0

---

# 12. P0-08 文件上传记录

## 输入

张三通过 IM 上传文件：

```text
未来城项目工程例会纪要.docx
```

并发送说明：

```text
上传一份未来城项目会议纪要。
```

## 期望结果

1. `messages` 写入文件消息。
2. 系统识别 `intent = file_upload`。
3. `files` 新增文件元数据。
4. 文件名、文件类型、上传人、event_id 有记录。
5. 系统回复文件编号。

## 回复示例

```text
文件已归档。
文件编号：FILE-20260605-000001
```

## 通过标准

文件上传可形成元数据记录。

等级：P0

---

# 13. P0-09 查询未完成任务

## 输入

张三发送：

```text
查一下未来城项目还有哪些未完成任务？
```

## 期望结果

1. `messages` 写入。
2. 系统识别 `intent = query`。
3. 查询 `tasks` 中未完成任务。
4. 通过 IM 返回任务列表。
5. 无结果时返回“暂无未完成任务”。

## 回复示例

```text
未来城项目当前未完成任务：
1. 1号楼入口整改，责任人：王五，截止：下周五
```

## 通过标准

可完成基础数据库查询并回复。

等级：P0

---

# 14. P0-10 Agent 回复入库

## 输入

触发任意业务成功回复，例如事件录入。

## 期望结果

1. 用户收到 IM 回复。
2. 回复内容也写入 `messages`。
3. `direction = agent_to_user`。
4. 回复消息关联同一个 `event_id` 或 parent_event_id。

## 通过标准

系统回复也可追溯。

等级：P0

---

# 15. P0-11 数据库异常处理

## 前置条件

模拟数据库连接失败或写入失败。

## 输入

张三发送：

```text
记录一下，今天防水验收完成。
```

## 期望结果

1. 系统捕获异常。
2. 日志包含错误原因和 event_id。
3. 用户收到简短失败提示。
4. AstrBot 主流程不崩溃。

## 回复示例

```text
系统暂时无法完成记录，请稍后重试或联系管理员。
```

## 通过标准

异常可控，不导致系统整体不可用。

等级：P0

---

# 16. P0-12 意图识别失败降级

## 输入

张三发送：

```text
这个情况先按之前那个方案处理吧。
```

## 期望结果

1. 消息写入 `messages`。
2. 系统无法识别具体业务时降级为 `chat` 或 `unknown`。
3. 不创建错误业务数据。
4. 可选回复：已收到。

## 通过标准

识别失败不破坏数据。

等级：P0

# 17. P1-01 文档切片与向量化

# 22. 不通过判定

出现以下情况，MVP 不应进入试运行：

1. IM 消息无法稳定进入系统。
2. 消息不能入库。
3. 业务成功或失败没有任何反馈。
4. 数据库异常导致 AstrBot 主进程崩溃。
5. 未绑定用户可以直接写入正式业务数据。
6. 事件、任务、文件没有任何可追溯编号。

---

# 23. MVP试运行通过标准

P0 用例全部通过，即可进入内部试运行。

P1 用例可逐步补齐，不阻塞试运行。

试运行阶段重点观察：

1. 用户是否愿意通过 IM 录入信息。
2. 消息记录是否完整。
3. 事件、任务、文件是否能被找回。
4. 查询结果是否有用。
5. 异常是否可排查。
