# 17-架构原则.md

# 一、项目定位

TeamBrain不是一个AstrBot插件。

TeamBrain是一个独立的企业知识大脑系统。

当前阶段：

```text
AstrBot
=
宿主平台

TeamBrain
=
业务系统
```

AstrBot仅承担：

1. 消息接入
2. 消息发送
3. 插件生命周期管理

业务逻辑全部归属于TeamBrain。

---

# 二、总体架构

```text
QQ

  ↓

AstrBot Adapter

  ↓

TeamBrain Core

  ↓

PostgreSQL + pgvector

  ↓

Knowledge Base
```

---

# 三、分层原则

采用五层结构：

```text
Adapter Layer

↓

Application Layer

↓

Domain Layer

↓

Infrastructure Layer

↓

Storage Layer
```

---

# 四、Adapter层职责

负责：

```text
接收消息
发送消息
事件监听
命令注册
```

禁止：

```text
业务逻辑
数据库访问
知识库访问
LLM调用
```

---

# 五、Application层职责

负责：

```text
流程编排
调用Service
事务协调
```

允许：

```text
TaskApplicationService
MeetingApplicationService
QueryApplicationService
```

---

# 六、Domain层职责

负责：

```text
业务规则
领域模型
状态流转
```

禁止：

```text
SQL
HTTP
AstrBot对象
```

---

# 七、Infrastructure层职责

负责：

```text
LLM
Embedding
向量库
文件系统
调度器
FastAPI
```

---

# 八、Storage层职责

负责：

```text
PostgreSQL
pgvector
文件存储
```

---

# 九、AstrBot依赖约束

允许依赖：

```python
MessageDTO
UserDTO
GroupDTO
```

禁止依赖：

```python
AstrBotMessageEvent
AstrBotContext
AstrBotSession
```

领域层不得感知AstrBot存在。

---

# 十、MVP技术边界

采用：

```text
PostgreSQL
pgvector
BGE-M3
FastAPI
```

不采用：

```text
Neo4j
GraphRAG
LangGraph
多Agent协作
复杂工作流引擎
```

以上能力列入V2/V3规划。

---

# 十一、项目根原则

Project是唯一业务根聚合。

所有业务对象必须归属于Project。

禁止出现孤立业务实体。
