# 数据库表结构设计

## 1. 设计目标

本文件定义团队大脑 Agent 模块第一阶段所需的最小数据库结构。

第一阶段目标是支持以下闭环：

1. IM 消息入库。
2. 用户、公司、项目基础信息管理。
3. 业务流转单入库。
4. 通用项目事件入库。
5. 文件元数据记录。
6. 计划任务录入与提醒。
7. 权限规则校验。
8. 异常事件记录。

## 2. 数据库选型

第一阶段建议使用 PostgreSQL。

建议策略：

```text
单库多项目
通过 project_id 做逻辑隔离
通过权限表控制用户可见范围
```

暂不建议每个项目单独创建数据库文件，以降低早期开发和维护复杂度。

## 3. 通用字段约定

除特殊说明外，业务表建议包含以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigserial | 主键 |
| created_at | timestamp | 创建时间 |
| updated_at | timestamp | 更新时间 |
| is_deleted | boolean | 逻辑删除标记，默认 false |

时间字段第一阶段统一使用数据库本地时间或 UTC 时间，后续再统一时区策略。

## 5. im_message：IM 通讯记录表

用于记录所有 IM 上行与下行消息。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | bigserial | 主键 | 自增 ID |
| event_id | varchar(64) | 非空，索引 | 全局事件 ID |

| im_source | varchar(32) | 非空 | qq / wecom / dingtalk / feishu |
| conversation_type | varchar(16) | 非空 | group / private |

| group_id | varchar(128) | 可空 | 群 ID |
| sender_id | varchar(128) | 非空，索引 | 发送人 ID |
| sender_name | varchar(64) | 默认空 | 发送人名称 |
| receiver_id | varchar(128) | 可空 | 接收人 ID |
| msg_type | varchar(32) | 非空 | text / image / file / voice / video / card |
| direction | varchar(32) | 非空 | user_to_agent / agent_to_user / system |
| content | text | 默认空 | 文本内容或 JSON 字符串 |
| file_ids | jsonb | 默认 [] | 关联文件 ID 列表 |
| project_id | bigint | 可空，索引 | 关联项目 |
| raw_payload | jsonb | 可空 | IM 原始消息 |

建议索引：

```sql

create index idx_im_message_flow_id on im_message(flow_id);
create index idx_im_message_conversation_id on im_message(conversation_id);
create index idx_im_message_sender_id on im_message(sender_id);
create index idx_im_message_project_id on im_message(project_id);
```

## 20. 示例数据流

用户发送：

```text
记录一下，今天1号楼地下室防水验收完成。
```

数据写入顺序：

```text
1. im_message 写入原始通讯记录
2. business_flow_instance 创建 event_record 流程
3. business_flow_log 写入“意图识别成功”
4. business_flow_log 写入“鉴权通过”
5. project_event 写入结构化事件
6. business_flow_instance 更新为 completed
7. im_message 写入 Agent 回复消息
```
