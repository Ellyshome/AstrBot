# 05-核心领域模型

## 1. 模型原则

系统采用：

```text
Entity + Event
```

Entity 表示当前状态，Event 表示发生过的变化。

---

## 2. MVP 核心对象

MVP 只保留以下核心对象：

```text
User
Project
Conversation
Message
File
Meeting
Task
Event
KnowledgePackage
DocumentChunk
```

---

## 3. User

User 表示系统用户。

职责：

```text
触发消息
上传文件
创建会议
创建任务
查询信息
```

与 IM 账号通过 `user_im_bindings` 关联。

---

## 4. Project

Project 是业务数据的主要容器。

关联：

```text
Project 1:N File
Project 1:N Meeting
Project 1:N Task
Project 1:N Event
Project N:M User
```

---

## 5. Conversation

Conversation 表示 IM 会话，包括：

```text
群聊
单聊
```

一个 Conversation 包含多条 Message。

---

## 6. Message

Message 是 IM 原始交互记录。

原则：

```text
所有 IM 消息必须先入 messages
```

Message 不一定产生正式业务数据。

---

## 7. File

File 表示文件元数据。

文件本体可存于：

```text
本地路径
MinIO
AstrBot 原始文件地址
```

数据库只保存元数据和存储路径。

---

## 8. Meeting

Meeting 表示会议记录或会议纪要。

来源：

```text
IM 文本
上传文件
后续语音转文字
```

Meeting 可生成 Task。

---

## 9. Task

Task 表示需要执行的工作项。

Task 与 Event 区别：

```text
Event：已经发生
Task：需要执行
```

Task 可以来源于：

```text
用户直接创建
会议纪要抽取
事件触发
```

---

## 10. Event

Event 是系统可追溯事件记录。

MVP 事件类型：

```text
im_message_received
business_event_recorded
file_uploaded
meeting_recorded
task_created
query_requested
system_error
```

后续再扩展更细事件分类。

---

## 11. KnowledgePackage

KnowledgePackage 表示知识包。

MVP 必须支持至少一个默认知识包：

```text
公司制度与业务流程知识包
```

该知识包用于维护：

```text
公司规章制度
既定业务流程
标准作业指引
常用模板
管理办法
审批规则说明
```

问答时，如果系统判断问题需要公司制度或既定流程支持，应优先检索该知识包。

---

## 12. DocumentChunk

DocumentChunk 表示文档切片，用于简单 RAG 查询。

来源：

```text
制度流程知识包文件
项目文件
会议纪要
```

MVP 要求：

```text
制度流程知识包文件必须生成 DocumentChunk
普通项目文件可后续增强
```

---

## 13. 核心关系

```text
User → Message
Message → Event / File / Meeting / Task
Project → File / Meeting / Task / Event
Meeting → Task
KnowledgePackage → File
File → DocumentChunk
KnowledgePackage → DocumentChunk
```

---

## 14. 入库例外原则

正式业务数据应尽量归属 User 和 Project。

但以下数据允许先入库：

```text
未知用户消息
未识别项目消息
意图未知消息
异常消息
```

这些数据必须标记状态，后续人工或系统补全。
