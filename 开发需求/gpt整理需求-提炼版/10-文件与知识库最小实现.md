# 10-文件与知识库最小实现

## 1. MVP 目标

MVP 不建设完整知识演化系统，但需要维护一个“公司制度与业务流程知识包”。

该知识包用于存放：

```text
公司规章制度
既定业务流程
标准作业指引
常用模板
管理办法
审批规则说明
```

目标：

```text
文件能归档
文件能关联项目和消息
制度流程资料能进入知识包
文件内容可切片
问答时如需要公司数据支持，优先检索制度流程知识包
用户可进行类似普通 RAG 系统的问答
```

---

## 2. 文件存储策略

MVP 文件分两层：

```text
文件本体：本地路径或 MinIO
文件元数据：PostgreSQL files 表
```

如果为了快速启动，可先保存 AstrBot 提供的文件路径，后续再迁移 MinIO。

---

## 3. 文件元数据

必须保存：

```text
文件名
文件类型
文件大小
上传人
来源消息
项目
存储路径
上传时间
解析状态
```

---

## 4. MinIO 使用策略

MinIO 建议进入 MVP，但不是强制。

启用时路径建议：

```text
/project/{project_id}/files/{file_id}/{filename}
```

未启用时：

```text
storage_path 保存本地或 AstrBot 原始文件地址
```

---

## 5. 知识包

MVP 必须支持至少一个默认知识包：

```text
公司制度与业务流程知识包
```

该知识包优先收录：

```text
公司规章制度
既定业务流程
部门管理办法
流程说明文件
标准模板
历史确认过的操作指引
```

知识包应支持启用/停用和优先级配置。

---

## 6. 文档切片

制度流程知识包必须支持 `document_chunks`。

普通项目文件的切片可选，制度流程类文件的切片建议作为 MVP 必做。

支持文件类型优先级：

```text
Markdown
TXT
DOCX
PDF
```

图片 OCR 后置。

---

## 7. pgvector

如果启用问答增强，使用 PostgreSQL + pgvector。

避免 MVP 阶段部署独立向量数据库。

---

## 8. 简单查询

MVP 查询优先级：

```text
1. 判断问题是否需要公司制度、规章、既定流程支持
2. 如需要，优先检索“公司制度与业务流程知识包”
3. 再查询结构化业务数据，如 tasks / files / meetings / events
4. 必要时检索项目文件或普通文档切片
5. 最后生成回答
```

不要一开始依赖复杂 RAG，但必须保证制度流程类问题优先搜索库内资料。

---

## 9. Query Agent 最小能力

Query Agent 支持：

```text
查未完成任务
查最近文件
查最近会议
查最近事件
根据 document_chunks 查文档内容
判断问题是否需要制度流程依据
优先检索公司制度与业务流程知识包
```

---

## 10. 不做内容

MVP 不做：

```text
Document → Fact → Knowledge → Case → Standard 自动演化
自动生成企业标准
复杂知识可信度体系
知识图谱推理
GraphRAG
```
