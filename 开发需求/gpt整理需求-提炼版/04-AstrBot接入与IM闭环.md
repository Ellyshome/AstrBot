# 04-AstrBot接入与IM闭环

## 1. 目标

本文件定义 MVP 阶段 AstrBot 与团队大脑模块的接入方式。

目标闭环：

```text
IM 消息
→ AstrBot
→ 团队大脑插件
→ 标准化
→ 入库
→ 意图识别
→ 业务处理
→ 回复 IM
```

---

## 2. 插件职责

AstrBot 插件只做接入层。

允许：

```text
接收消息
获取发送人、群、附件信息
调用团队大脑主入口
发送回复
记录入口异常
```

禁止：

```text
直接写业务表
直接判断复杂业务规则
直接调用 LLM 决策
直接拼 SQL
直接替换 AstrBot 主 Agent
直接修改 AstrBot core
```

---

## 3. 分域接管规则

团队大脑插件采用分域接管。

接管条件：

```text
单聊中发给团队大脑的消息
群聊中 @团队大脑 / @机器人 的消息
明确业务指令，如“记录一下”“任务：”“会议纪要：”“查一下”“上传文件”
被配置为团队大脑项目群的会话
管理员配置的强接管会话
```

不接管条件：

```text
普通闲聊
无关群聊消息
AstrBot 管理命令
其他插件命令
无法判断且未 @ 机器人的群聊消息
```

处理结果：

```text
命中团队大脑业务域：交给 TeamBrain Router Agent
未命中团队大脑业务域：放行给 AstrBot 原主 Agent / 其他插件
```

---

## 4. 运行模式

MVP 支持三种运行模式配置：

| 模式 | 行为 | 适用阶段 |
|---|---|---|
| 观察模式 | 只记录消息，不主动回复，不阻断 AstrBot 原流程 | 新群接入、试观察 |
| 协作模式 | 命中业务意图时接管，未命中放行 | MVP 默认 |
| 托管模式 | 指定会话内团队大脑优先处理大部分消息 | 后期成熟后 |

MVP 默认使用：

```text
协作模式
```

## 5. 标准消息结构

所有消息统一转换为：

```json
{
  "event_id": "EV-20260605-000001",
  "source": "astrbot",
  "im_platform": "qq",
  "conversation_type": "group",
  "conversation_id": "group_123456",
  "group_id": "group_123456",
  "sender_im_id": "qq_10001",
  "sender_name": "张三",
  "receiver_im_id": null,
  "message_type": "text",
  "content": "记录一下，今天防水验收完成",
  "attachments": [],
  "raw_payload": {},
  "received_at": "2026-06-05T10:00:00"
}
```

---

## 6. event_id

每条进入系统的 IM 消息必须生成 `event_id`。

用途：

```text
追踪消息
关联业务事件
关联文件
关联任务
关联回复
定位异常
```

---

## 7. 用户映射

映射关系：

```text
im_platform + im_user_id → users.id
```

处理策略：

| 情况 | 策略 |
|---|---|
| 已绑定用户 | 正常执行业务 |
| 未绑定用户 | 消息入库，但限制正式业务写入 |
| Agent 回复 | direction = agent_to_user |
| 系统事件 | sender 标记为 system |

---

## 8. 消息入库原则

所有消息先写入 `messages`。

即使：

```text
用户未绑定
项目未识别
意图识别失败
业务处理失败
```

也必须保留原始消息。

---

## 9. MVP 意图类型

```text
chat：普通消息
event_record：事件录入
file_upload：文件上传
meeting_record：会议记录
task_record：任务创建
query：查询问答
unknown：未知
```

---

## 10. 路由优先级

```text
附件消息
→ 查询意图
→ 任务意图
→ 会议意图
→ 事件录入意图
→ 普通消息
```

---

## 11. 回复策略

| 场景 | 回复 |
|---|---|
| 单聊普通消息 | 可回复 |
| 群聊普通消息 | 默认不回复 |
| 群聊 @Agent | 回复 |
| 事件录入成功 | 回复 |
| 任务创建成功 | 回复 |
| 文件上传成功 | 回复 |
| 查询问答 | 回复 |
| 处理失败 | 回复简短错误 |

Agent 回复也应写入 `messages`。

---

## 12. 典型流程

### 12.1 事件录入

```text
用户：记录一下，今天未来城项目防水验收完成
→ 标准化消息
→ 写入 messages
→ Router 识别 event_record
→ Event Handler 写入 events
→ 回复：已记录该事件
```

### 12.2 任务创建

```text
用户：任务：王五下周五前完成入口整改
→ 写入 messages
→ Router 识别 task_record
→ Task Handler 写入 tasks
→ 回复：已创建任务
```

### 12.3 查询

```text
用户：查一下未来城项目还有哪些未完成任务
→ 写入 messages
→ Router 识别 query
→ Query Agent 查询 tasks
→ 回复任务列表
```

### 12.4 制度流程知识包问答

```text
用户：按照公司制度，材料进场验收需要提交哪些资料？
→ 写入 messages
→ Router 识别 query
→ Query Agent 判断需要公司制度或流程依据
→ 优先检索公司制度与业务流程知识包
→ 基于库内资料生成回复
```

---

## 13. 异常处理

原则：

```text
消息先留痕
业务可失败
系统不崩溃
用户有提示
日志可追踪
```

异常类型：

```text
消息解析失败
用户未绑定
数据库写入失败
业务识别失败
回复发送失败
```

---

## 14. 完成标准

1. AstrBot 能把消息交给团队大脑模块。
2. 团队大脑插件能判断接管或放行，未接管消息不影响 AstrBot 原流程。
3. 消息能标准化。
4. 所有消息能入库。
5. 系统能识别基础意图。
6. 基础业务能写入对应表。
7. 用户能收到回复。
8. 异常可记录。
