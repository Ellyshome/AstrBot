# 09-权限与审计

## 1. MVP 权限目标

MVP 权限只解决基本安全问题：

```text
谁发的消息
是否是已绑定用户
是否属于相关项目
是否允许写入正式业务数据
```

完整 RBAC 后置。

---

## 2. MVP 角色

第一阶段只保留：

```text
admin
member
guest
```

| 角色 | 权限 |
|---|---|
| admin | 管理用户、项目、绑定关系 |
| member | 录入事件、文件、会议、任务，查询有权项目 |
| guest | 仅允许消息留痕，不允许正式业务写入 |

---

## 3. 用户绑定规则

已绑定用户：

```text
可按权限执行业务
```

未绑定用户：

```text
消息入库
禁止正式业务写入
回复绑定提示
```

---

## 4. 项目权限

MVP 使用 `project_members` 判断用户是否属于项目。

规则：

```text
用户属于项目 → 可录入和查询该项目数据
用户不属于项目 → 不允许查询或修改该项目正式数据
项目未识别 → 可暂存为未绑定项目数据
```

---

## 5. Agent 权限原则

Agent 不拥有独立权限。

```text
Agent 只能继承当前用户权限
```

禁止：

```text
Agent 绕过用户权限读取其他项目数据
Agent 自动执行高风险操作
Agent 自动批准新业务流
```

---

## 6. 高风险操作

MVP 阶段以下操作不允许 Agent 自动执行：

```text
删除项目
删除文件
关闭项目
权限变更
审批付款
合同归档确认
```

这些操作后续必须人工确认。

---

## 7. 审计范围

必须审计：

```text
消息接收
意图识别
业务写入
查询请求
Agent 回复
权限拒绝
系统异常
```

审计可先写入：

```text
events
日志文件
```

---

## 8. 审计字段

建议记录：

```text
event_id
user_id
message_id
action
result
payload
created_at
```

---

## 9. 权限失败回复

示例：

```text
已收到消息，但尚未识别您的系统身份。请联系管理员绑定账号后再进行业务录入。
```

```text
您暂无该项目的操作权限，本次请求已记录但未写入正式业务数据。
```
