## 1. 文档定位

本目录是基于原 `gpt整理需求` 目录 01-17 号文档重新提炼形成的开发启动版文档。

原目录定位：

```text
资料池 + 架构参考
```

本目录定位：

```text
MVP 第一阶段开发依据
```

本目录不追求覆盖企业数字大脑的全部长期能力，而是明确第一阶段如何尽快跑通系统。

正式开发时，团队大脑 Agent 应作为 AstrBot 插件开发，放置在 AstrBot 官方插件目录：

```text
d:\app\AstrBot\data\plugins\team_brain_agent
```

本提炼版需求文档建议复制一份到插件目录内：

```text
d:\app\AstrBot\data\plugins\team_brain_agent\docs\requirements
```

`开发需求` 目录继续作为需求整理与历史资料区，不作为插件运行目录。

---

## 2. 第一阶段核心目标

第一阶段只验证一个核心闭环：

```text
AstrBot / IM 消息接入
→ 消息标准化
→ 消息入库
→ 意图识别
→ 事件 / 文件 / 会议 / 任务处理
→ 简单查询
→ IM 回复
```

只要该闭环可用，系统就可以进入内部试运行。

## 4. MVP 可选范围

MVP 可选：

```text

pgvector 文档切片检索
```

## 8. 执行原则

1. 先跑通，再完善。
2. 先 IM 入口，后 Web 平台。
3. 先消息留痕，后智能处理。
4. 先固定流程，后配置化 Workflow。
5. 先简单状态，后完整 State Engine。
6. 先 PostgreSQL，后 Neo4j。
7. 先 Handler，后专项 Agent。
8. 先分域接管，后考虑专用实例托管；MVP 不夺舍 AstrBot 主 Agent。

---

## 9. 结论

本目录的核心作用是压缩范围、明确边界、支撑开发启动。

第一阶段不得以长期架构为由扩大 MVP 范围。
