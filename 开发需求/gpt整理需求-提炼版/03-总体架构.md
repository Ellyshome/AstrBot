# 03-总体架构

## 1. 架构目标

第一阶段架构目标是支持 IM 入口下的最小业务闭环，同时保留后续扩展到知识库、工作流、图谱和多 Agent 协同的空间。

---

## 2. MVP 总体架构

```text
IM 平台
  ↓
AstrBot
  ↓
团队大脑 AstrBot 插件
  ↓
IM 消息标准化层
  ↓
Router Agent
  ├─ Event Handler
  ├─ File Handler
  ├─ Meeting Handler
  ├─ Task Handler
  ├─ Knowledge Package Service
  └─ Query Agent
  ↓
Service 层
  ↓
Repository / Infrastructure
  ↓
PostgreSQL / MinIO / pgvector
```

---

## 3. AstrBot 分域接管策略

第一阶段采用“插件级分域接管”，不直接夺舍 AstrBot 主 Agent，也不把 AstrBot 全局降级为纯 IM 路由接口。

定位如下：

```text
AstrBot：IM 接入层 + 插件运行宿主 + 通用会话能力保留
团队大脑：独立业务 Agent 系统，只接管命中特定业务域的消息
```

消息流转：

```text
IM 消息
→ AstrBot 平台接入
→ team_brain_agent 插件监听
→ 标准化与消息留痕
→ 判断是否属于团队大脑业务域
    ├─ 是：交给 TeamBrain Router Agent 接管
    └─ 否：放行给 AstrBot 原主 Agent / 其他插件
```

MVP 推荐运行模式为“协作模式”：

```text
命中业务意图时接管
未命中时放行
```

禁止在 MVP 阶段直接修改 AstrBot 主 Agent 或 AstrBot core。

---

## 4. 第一阶段主入口

第一阶段主入口为：

```text
AstrBot 插件
```

插件只负责：

```text
接收消息
转换消息
调用团队大脑模块
发送回复
```

插件不负责复杂业务判断。

插件正式开发目录为：

```text
d:\app\AstrBot\data\plugins\team_brain_agent
```

不应放入 AstrBot 基座核心目录：

```text
d:\app\AstrBot\astrbot\core
```

也不应放入 AstrBot 内置插件目录：

```text
d:\app\AstrBot\astrbot\builtin_stars
```

原因是团队大脑属于业务插件，应与 AstrBot 基座解耦，避免后续升级冲突。

---

## 5. 模块化单体

第一阶段采用模块化单体，不拆微服务。

原因：

```text
开发快
调试简单
部署简单
业务边界还在变化
```

后续如模块稳定，再拆分 API、Worker、Scheduler 等独立服务。

---

## 6. 数据存储架构

MVP 强制：

```text
PostgreSQL
```

MVP 建议：

```text
MinIO：文件本体存储
pgvector：文档切片检索
```

MVP 可选：

```text
Redis：缓存、短期状态、简单队列
```

MVP 不做：

```text
Neo4j
Kafka
独立 Vector DB
```

---

## 7. 数据源原则

PostgreSQL 是唯一事实源。

```text
业务实体
消息记录
任务状态
文件元数据
事件记录
权限关系
```

必须以 PostgreSQL 为准。

MinIO、pgvector、Redis、Neo4j 都是派生或辅助层。

---

## 8. Agent 与 Handler 分工

MVP 不拆大量 Agent。

```text
Router Agent：识别意图，分派处理
Query Agent：处理简单查询、问答，并优先检索制度流程知识包
Handler：处理事件、文件、会议、任务等具体意图
Service：执行业务规则
Repository：执行数据库操作
```

后续 Handler 稳定后，可升级为专项 Agent。

---

## 9. 长期演进架构

后续演进方向：

```text
固定 Handler
→ Workflow Runtime
→ LangGraph 编排
→ 多 Agent 协同
→ Neo4j 知识图谱
→ 事件总线
→ 企业知识演化
```

---

## 10. MVP 禁止事项

1. 不为了未来可能性提前拆微服务。
2. 不在插件入口写业务逻辑。
3. 不直接夺舍或替换 AstrBot 主 Agent。
4. 不在 MVP 阶段把 AstrBot 全局降级为纯 IM Gateway。
5. 不在 Agent 中直接写 SQL。
6. 不强制建设 Neo4j。
7. 不一开始实现完整 Workflow Engine。
8. 不把所有业务处理都拆成 Agent。

---

## 11. 结论

第一阶段架构重点是：

```text
IM 入口清晰
消息留痕可靠
业务处理简单
数据结构可扩展
后续架构有演进空间
```
